# คู่มือเตรียมสอบ: เจาะลึกโค้ด Smart Deal Rider 🚀

## 1. โครงสร้างโปรเจกต์และไลบรารีสำคัญ
- โครงสร้างใช้ **Expo Router** (File-based routing) ทำให้ไฟล์ในโฟลเดอร์ `src/app/` ทำหน้าที่เป็นหน้าจอและเส้นทาง (Route) ทันที
- **Navigation:**
  - การกำหนดแท็บเมนูด้านล่าง (Bottom Tabs) อยู่ที่ไฟล์ `src/app/(tabs)/_layout.tsx` ซึ่งควบคุมหน้า เรดาร์ (`index`), ออเดอร์ (`jobs`), กระเป๋าเงิน (`wallet`), และประวัติ (`history`)
- **ไลบรารีสำคัญ (อ้างอิงจาก `package.json`):**
  - `expo-router`: ระบบนำทางระหว่างหน้า
  - `react-native-maps`: ระบบแสดงแผนที่ หมุด (Marker) พิกัดร้านค้าและลูกค้า
  - `axios`: ตัวจัดการ HTTP Request สำหรับยิง API ไปยังระบบ Backend (`server.js`)
  - `expo-camera`, `expo-image-picker`: โมดูลถ่ายรูปและอัปโหลดรูปภาพ เช่น ถ่ายป้ายทะเบียนรถตอนสมัคร หรือถ่ายรูปยืนยันตอนส่งของสำเร็จ
  - `react-native-safe-area-context`: ป้องกัน UI ทับขอบจอบนมือถือ (เช่น ติ่งกล้องหน้า หรือขอบมน)

## 2. เจาะลึกโค้ดทุกหน้าจอ (File-by-File Breakdown)

**2.1 หน้าเข้าสู่ระบบ (`src/app/login.tsx`)**
- **ตัวแปร State (`useState`):**
  - `email`, `password`: เก็บค่าอีเมลและรหัสผ่าน
  - `loading`: สถานะล็อกหน้าจอขณะรอดึงข้อมูลจากเซิร์ฟเวอร์
  - `showPassword`: ค่า boolean สำหรับเปิด/ปิดรหัสผ่าน
- **ลอจิก / ฟังก์ชันหลัก (`handleLogin`):**
  - ตรวจสอบว่ากรอกข้อมูลครบหรือไม่
  - ยิง API `POST /rider/login` พร้อมอีเมลและรหัสผ่าน
  - หากสำเร็จ จะได้ `token` และ `rider` กลับมา แล้วส่งไปเก็บใน AuthContext ด้วยคำสั่ง `login(token, rider)` 
  - หากบัญชียังไม่ผ่านการอนุมัติ (Backend ส่ง 403 และ status = rejected กลับมา) จะ redirect ไรเดอร์ไปหน้าสมัครสมาชิกใหม่พร้อมเหตุผลว่าทำไมถึงถูกปฏิเสธ

**2.2 หน้าสมัครสมาชิกไรเดอร์ (`src/app/register.tsx`)**
- **ตัวแปร State (`useState`):**
  - `step`: ลำดับขั้นตอนการกรอกฟอร์ม (1-3 ขั้นตอน)
  - ข้อมูลต่างๆ เช่น `email`, `password`, `phone`, `realName`, `vehicleType`, `vehiclePlate`, `licenseNumber`
  - `idCardImage`, `vehicleDocImage`, `licenseImage`: เก็บ path ของรูปที่ถูกอัปโหลด
- **ลอจิก / ฟังก์ชันหลัก:**
  - `pickImage`: ฟังก์ชันเปิดแกลอรี่รูปภาพ โดยใช้ `ImagePicker.launchImageLibraryAsync`
  - `handleNext` / `handlePrev`: ตรวจสอบความครบถ้วนของข้อมูลในแต่ละสเต็ป (Validation) แล้วเปลี่ยนตัวแปร `step` เพื่อไปหน้าถัดไป
  - `handleSubmit`: รวบรวมข้อมูลทั้งหมดใส่ object ชนิด `FormData` (เพื่อให้อัปโหลดไฟล์รูปได้) และส่งผ่าน XMLHttpRequest ไปยัง `POST /rider/register` เซิร์ฟเวอร์จะบันทึกข้อมูลเหล่านี้ลงในตาราง `riders` เป็นสถานะ "รออนุมัติ"

**2.3 หน้าแดชบอร์ดรับงาน - เรดาร์ (`src/app/(tabs)/index.tsx`)**
- **ตัวแปร State (`useState`):**
  - `isOnline`: ควบคุมการเปิด/ปิดรับงาน (สวิตช์ Online/Offline)
  - `jobs`: อาร์เรย์เก็บข้อมูลงาน (ออเดอร์) ใหม่ที่รอคนกดรับ
  - `activeJob`: งานปัจจุบันที่รับไว้แล้วแต่ยังทำไม่เสร็จ
  - `wallet`: ข้อมูลรายได้และจำนวนงานที่ทำสำเร็จในวันนี้
- **การทำงานอัตโนมัติ (Polling):**
  - ใน `useFocusEffect` มีการใช้ `setInterval` ตั้งเวลาเรียก `fetchJobs`, `fetchWallet`, และ `checkActiveDelivery` ทุกๆ **5 วินาที (5000ms)** เพื่อเช็กออเดอร์ใหม่โดยอัตโนมัติตลอดเวลา (ทำงานเฉพาะตอน `isOnline` เป็น true)
- **ลอจิก / ฟังก์ชันหลัก (`acceptJob(job)`):**
  - เมื่อไรเดอร์กดปุ่มรับงาน โค้ดจะยิง API ไปที่ `PUT /rider/deliveries/{order_id}/status` ส่งค่า `status: 'accepted'` เพื่อแย่งรับงาน
  - เมื่อรับสำเร็จ (Backend อัปเดตตาราง `deliveries` เรียบร้อย) โค้ดจะพาไปยังหน้าแผนที่ `/delivery/[id]` ทันที

**2.4 หน้าออเดอร์ของฉัน (`src/app/(tabs)/jobs.tsx`)**
- **ตัวแปร State (`useState`):**
  - `activeTab`: ควบคุมว่าจะดูแท็บ "กำลังดำเนินการ" หรือ "ส่งสำเร็จแล้ว"
  - `activeDeliveries`: อาร์เรย์เก็บออเดอร์ที่สถานะค้างอยู่
  - `completedDeliveries`: อาร์เรย์เก็บออเดอร์ที่เสร็จแล้ว (delivered หรือ completed)
- **การทำงานอัตโนมัติ (Polling):**
  - ใช้ `setInterval` ยิง API ทุกๆ **4 วินาที (4000ms)** เรียกข้อมูลผ่าน `GET /rider/{riderId}/history` จากนั้นนำข้อมูลที่ได้มา `filter` แยกเก็บลง state `activeDeliveries` และ `completedDeliveries`

**2.5 หน้าแผนที่นำทางและสถานะการจัดส่ง (`src/app/delivery/[id].tsx`)**
- **ตัวแปร State (`useState`):**
  - `job`: เก็บรายละเอียดพิกัดร้านค้า (lat, lng), พิกัดลูกค้า, ชื่อร้าน, จำนวนเงินค่ารอบ
  - `status`: เก็บสถานะของการจัดส่งปัจจุบัน
- **ลอจิกแผนที่:**
  - สร้าง `MapView` โดยคำนวณ `region` (พิกัดศูนย์กลาง) จากละติจูด/ลองจิจูดของร้านค้า
  - ฟังก์ชัน `openNavigation`: ใช้คำสั่ง `Linking.openURL` เพื่อเปิดแอป Google Maps นำทางไปยังร้านค้าหรือลูกค้า
- **ลอจิกฟังก์ชัน (`updateStatus`):**
  - ตัวแปร `next` จะคำนวณว่าปุ่มต่อไปไรเดอร์ต้องกดอะไร (เช่น จาก "มารับอาหาร" กลายเป็น "กำลังไปส่ง") 
  - เมื่อกด โค้ดจะยิง API ไปที่ `PUT /rider/deliveries/{order_id}/status` อัปเดตสถานะล่าสุดกลับไปยังระบบ Backend

**2.6 หน้ากระเป๋าเงิน (`src/app/(tabs)/wallet.tsx`)**
- **ตัวแปร State (`useState`):**
  - `walletData`: เก็บยอดเงินคงเหลือ (`balance`), รายได้วันนี้ (`todayIncome`), จำนวนงาน, และรายการเดินบัญชี (`history`)
  - `withdrawAmount`: จำนวนเงินที่กรอกเพื่อถอนออก
- **ลอจิก / ฟังก์ชันหลัก (`handleWithdraw`):**
  - มีการเช็กก่อนว่าจำนวนเงินถอน (withdrawAmount) มากกว่า 0 และน้อยกว่าหรือเท่ากับ ยอดคงเหลือ (balance) หรือไม่
  - ถอนเงินโดยยิง API `POST /rider/wallet/withdraw` โดย Backend จะนำไปหักลบยอดและบันทึกประวัติการถอน (ประเภท `debit`) ลงในตารางธุรกรรมของไรเดอร์

**2.7 หน้าประวัติงานและรายได้รายเดือน (`src/app/(tabs)/history.tsx` และ `src/app/income.tsx`)**
- **`history.tsx`:** ยิง API `GET /rider/{riderId}/history` เพื่อดึงออเดอร์ทั้งหมดมาแสดงผล และคำนวณตัวแปร `total_jobs`, `total_earnings`
- **`income.tsx`:** ดึงประวัติเช่นเดียวกัน แต่ใช้ลอจิกวันที่ (`date.getMonth()`) เพื่อกรองเฉพาะออเดอร์ที่เกิดใน "เดือนปัจจุบัน" และเปรียบเทียบกับ "เดือนที่แล้ว" เพื่อนำไปพล็อตเป็นกราฟและคำนวณค่า % เปรียบเทียบ

## 3. เจาะลึกลอจิกการรับงานและเปลี่ยนสถานะการจัดส่ง (Delivery State Machine)

Flow วงจรชีวิตของ 1 ออเดอร์ในแอปไรเดอร์มี 5 ขั้นตอนหลัก การเปลี่ยนสถานะทุกครั้งแอปจะสั่งยิง API `PUT /rider/deliveries/{order_id}/status` ส่งไปอัปเดตตาราง `deliveries` และ `orders` ในฐานข้อมูล

1. **งานใหม่ (Pending):** เมื่อลูกค้าสั่งอาหาร ออเดอร์จะแสดงขึ้นที่หน้าเรดาร์ของไรเดอร์ (อิงจากระยะทาง)
2. **`accepted` (รับงานแล้ว):**
   - **โค้ดสั่งการ:** กดปุ่มรับงานใน `index.tsx`
   - **ฐานข้อมูล:** ผูก `rider_id` เข้ากับ `order_id` และเปลี่ยน status = `accepted`
3. **`arriving_shop` (ถึงร้านค้า):**
   - **โค้ดสั่งการ:** ไรเดอร์เดินทางไปถึงหน้าแผนที่ แล้วกดปุ่ม "ฉันมาถึงร้านแล้ว" ในไฟล์ `delivery/[id].tsx`
   - **ฐานข้อมูล:** status = `arriving_shop`
4. **`picked_up` (รับอาหารแล้ว):**
   - **โค้ดสั่งการ:** ไรเดอร์รับของจากร้าน แล้วกดปุ่ม "ยืนยันรับสินค้าแล้ว"
   - **ฐานข้อมูล:** status = `picked_up`
5. **`delivering` (กำลังจัดส่ง):**
   - **โค้ดสั่งการ:** ไรเดอร์เริ่มสตาร์ทรถ แล้วกด "เริ่มออกจัดส่งให้ลูกค้า"
   - **ฐานข้อมูล:** status = `delivering`
6. **`delivered` / `completed` (จัดส่งสำเร็จ):**
   - **โค้ดสั่งการ:** เมื่อถึงบ้านลูกค้า ปุ่มสุดท้ายจะพาไรเดอร์ไปที่หน้ากล้อง (`proof-of-delivery/[id].tsx`) เพื่อถ่ายภาพหลักฐาน เมื่ออัปโหลดเสร็จ สถานะจะถูกอัปเดตเป็นเสร็จสมบูรณ์
   - **ฐานข้อมูล:** ระบบหลังบ้าน (Backend) จะเพิ่มเงินค่ารอบเข้า Wallet ของไรเดอร์ทันที และออเดอร์ถือว่าจบการทำงาน

## 4. จุดแก้ไขโค้ดด่วนเวลาอาจารย์สั่งแก้ในห้องสอบ (Quick Fix Reference)

📍 **หากอาจารย์สั่ง "ลดภาระ Server โดยปรับให้เรียกดึงข้อมูลออเดอร์ช้าลง" (Change Polling Rate)**
- **ตำแหน่งไฟล์:** `src/app/(tabs)/index.tsx` และ `src/app/(tabs)/jobs.tsx`
- **จุดที่ต้องแก้:** มองหา `setInterval(..., 5000)` ใน `index.tsx` และ `setInterval(..., 4000)` ใน `jobs.tsx` ภายในบล็อกของ `useFocusEffect` เปลี่ยนตัวเลข (มิลลิวินาที) ให้สูงขึ้น เช่น `10000` (10 วินาที)

📍 **หากอาจารย์สั่ง "เปลี่ยนข้อความปุ่มกดวงจรสถานะการรับงาน (State Machine)"**
- **ตำแหน่งไฟล์:** `src/app/delivery/[id].tsx`
- **จุดที่ต้องแก้:** เลื่อนหาโค้ดส่วนของตัวแปร `const next = ...` และ `steps` สามารถเปลี่ยนข้อความภาษาไทยตรงป้ายกำกับ (Label) ได้เลย เช่น เปลี่ยน 'ฉันมาถึงร้านแล้ว' เป็น 'ถึงที่หมายแล้ว'

📍 **หากอาจารย์สั่ง "เพิ่มเงื่อนไข: ไรเดอร์ต้องถอนเงินขั้นต่ำ 100 บาทเท่านั้น"**
- **ตำแหน่งไฟล์:** `src/app/(tabs)/wallet.tsx`
- **จุดที่ต้องแก้:** ไปที่ฟังก์ชัน `handleWithdraw` ให้เพิ่มเงื่อนไข If ด้านบนสุด:
  ```javascript
  if (Number(withdrawAmount) < 100) {
    Alert.alert('ข้อผิดพลาด', 'ต้องถอนเงินขั้นต่ำ 100 บาท');
    return;
  }
  ```

📍 **หากอาจารย์สั่ง "เปลี่ยนธีมแอป หรือ แก้ไขสีปุ่มหลัก (Primary Color)"**
- **ตำแหน่งไฟล์:** หลายไฟล์ใน `src/app/` (เช่น `index.tsx`, `delivery/[id].tsx`, `_layout.tsx`)
- **จุดที่ต้องแก้:** สีหลักของแอปคือสีเขียวมรกต ค้นหาโค้ดสี `#059669` หรือ `#2e7d32` ในบรรทัด `StyleSheet.create` แล้ว replace ด้วยรหัสสีที่อาจารย์ต้องการ (เช่น สีแดง `#ef4444` หรือ สีฟ้า `#3b82f6`)
